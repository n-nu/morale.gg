# Boundary Change Request: Statistics Read-Derivation Module and Source Seams

- Request ID: BCR-20260927-005
- Requesting ticket: TKT-20260927-000024-001
- Requesting module: statistics
- Affected modules: audits, events, players, units
- Status: Approved
- Human approval: Approved by the human architectural owner on 2026-09-27

## Problem

The requested public statistics require coordinated reads from four authoritative
domains. No module currently owns shared window semantics, effective finalized-Audit
selection, raw metric aggregation, or attendance derivation. Implementing these
queries inside an existing source module would transfer ownership or duplicate
private persistence semantics.

## Existing Contract

Audits owns immutable finalized result history and command groups; Events owns
Event occurrence time and EventParticipation; Players owns Player identity and
UnitMembership history; Units owns persistent Unit identity and hierarchy. The
accepted Audit architecture explicitly leaves statistics calculation deferred.

## Missing Capability

A dedicated read-derived Statistics boundary and four minimum source seams:

- Audits -> Statistics: effective finalized-Audit observations, roles, results,
  Unit type, mandatory atomic-unit metadata, represented Unit/Event context, and
  command-group descendant structure.
- Events -> Statistics: canonical Event identity and occurrence time.
- Players -> Statistics: stable Player identity and membership-period eligibility
  at a supplied Event time.
- Units -> Statistics: public Unit identity, hierarchy/subtree resolution, and
  organizational relationships.

## Proposed Change

Register the `statistics` module and the four read-only contracts named above.
Contracts expose minimum domain facts and semantic read operations, not private
Prisma models, authority rows, Auth.js submitter identity, or mutation
operations. Audits owns the current-effective-finalized-Audit determination;
Events owns canonical Event occurrence time and its normalization; Statistics
owns the shared 14-day/30-day/all-time window policy and applies it to
Events-owned time. Statistics computes public DTOs at query time and owns no
source records.

Audits owns the semantic determination of the current effective finalized Audit
for an atomic Event unit and exposes it through the effective-Audit contract.
Statistics consumes that decision and must not reproduce Audit lifecycle or
future supersession predicates. Events owns canonical Event occurrence time and
its normalization through the Event-time contract. Statistics owns the
trailing 14-day (default), trailing 30-day, and all-time window policy and
applies those windows to Events-owned canonical time. All Ranker, Commander,
General, Unit, and attendance queries use the same Audits source seam and
Statistics window policy. The Players contract evaluates membership as of the
canonical Event date. The Units contract supports direct and descendant
subtree resolution without moving Unit type onto persistent Units.

## Alternatives Considered

- Put Statistics in Audits: rejected because aggregation spans Events, Players,
and Units and would broaden Audit ownership.
- Let Statistics query all source tables directly: rejected because it bypasses
module boundaries and private persistence.
- Add mutable aggregate tables now: rejected because MVP semantics require
query-time derivation and future supersession compatibility.
- Create one broad shared domain contract: rejected because four source owners
should retain independently evolvable, minimum read seams.

## Affected Consumers

- Statistics query/read services only.
- Future public statistics and simple leaderboard routes, through Statistics.

## Compatibility / Risk

The proposed contracts are additive and read-only. They do not alter current
Audit, Event, Player, Unit, membership, or command-group behavior. Main risks are
source leakage, accidental duplicate counting, use of Audit timestamps, and
silently blending Unit types; the ADR and contracts prohibit each.

No implementation, schema, index, cache, materialized view, scheduled job, or
supersession workflow is authorized by this BCR.
