# Boundary Change Request: Event Battle summary and Player-appearance averages

- Request ID: BCR-20261102-009
- Requesting ticket: TKT-20261102-000049-001
- Requesting module: events
- Affected modules: statistics; events
- Status: Approved
- Human approval: Approved by the requester through an explicit boundary and
  metric-semantics decision on 2026-11-02

## Problem

The public Event presentation needs side-level Tickets, pooled K/D, and Flag
Captures, plus per-Company average Kills, Deaths, and Assists. The current
Statistics-owned Event Battle DTO contains finalized Company totals and
individual Player results, but exposes neither side summaries nor averages.
Computing them in React would duplicate Statistics aggregation ownership.

## Existing Contract

`statistics-events-event-battle-reader` exposes side-separated atomic and
group hierarchy; per-Company K/D/A and pooled K/D; Tickets, Flag Captures,
Flag Losses, and Stars; and individual Player K/D/A/KDR. Existing Statistics
averages elsewhere are per Audit or qualifying Unit and do not define the
requested Event-scoped per-Player-appearance averages.

## Missing Capability

Add query-time, presentation-safe side summaries and per-Company averages to
the Event Battle DTO, derived from existing finalized observation values.

## Proposed Change

Extend the Statistics Event Battle read additively:

- Per-Company average Kills, Deaths, and Assists equal each finalized
  Company's Player-result total divided by its finalized Player appearance
  count. Zero-valued Player appearances remain in the denominator. The DTO
  identifies the count and does not invent a value when the count is zero.
- Side summaries aggregate finalized Company values only. Tickets and Flag
  Captures are summed from existing Company values. K/D is pooled finalized
  kills divided by pooled finalized deaths and uses the existing
  zero-denominator behavior. It is labeled K/D, not Average K/D.
- Preserve the current finalized-Audit source, pending states, result
  authority, calculations, and public-safe fields. No database or schema
  changes.
- Update the contract and discovery registry.

## Alternatives Considered

- Derive totals and averages in React: rejected because Statistics owns
  aggregation semantics and this would duplicate calculations in the
  consumer.
- Arithmetic mean of individual Player K/D ratios: rejected by the requester
  because excluding zero-death appearances is misleading and would not match
  the existing pooled K/D meaning.
- Rename pooled K/D to Average K/D: rejected because that label would misstate
  the metric.
- Persist derived values or modify source Audit/Event data: rejected; the
  request is a query-time presentation refinement and requires no schema or
  source-semantic change.

## Affected Consumers

- Public Event presentation in `/events/[eventId]`.
- Statistics Event Battle reader tests and any typed consumers of its DTO.

## Compatibility / Risk

The DTO grows additively and remains a public, query-time read. Existing fields
and calculations do not change; no migration is required. Risks are incorrect
denominators or inclusion of pending observations. These are bounded by the
approved per-finalized-Player-appearance definition and tests for pending and
zero-player states. The public Event consumer is updated with the contract.

## Approval Decision

Approved for the bounded additive Statistics DTO/contract change and the
semantics above. Average Kills/Deaths/Assists use finalized Player appearances,
including zero-valued appearances. K/D remains pooled finalized kills divided
by pooled finalized deaths, with the established zero-denominator form, and
must not be labeled Average K/D. No schema migration or changes to Event,
Audit, result, Ticket, or existing Statistics calculation semantics are
approved.

## Decision Owner

The human requester.

## Result

Implemented under TKT-20261102-000049-001: added finalized Company averages
and pooled side summaries to the Statistics-owned Event Battle DTO, updated
the public Event presentation and contract, and verified the existing source
and result semantics remain unchanged.
