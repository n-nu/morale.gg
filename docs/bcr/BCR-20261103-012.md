# Boundary Change Request: Statistics Reads for the Public Player Profile

- Request ID: BCR-20261103-012
- Requesting ticket: TKT-20261103-000053-001
- Requesting module: statistics
- Affected modules: statistics; events; units; public Player presentation
- Status: Approved
- Human approval: Approved by the requester through the explicit boundary
  approval response on 2026-11-03

## Problem

The public Player profile currently assembles global Ranker, Commander, and
General aggregates and selects a Player's row. It has no Statistics-owned
per-Player, per-Event result read, so the profile cannot provide the requested
chronological history or ensure filtered summaries and detail rows use one
canonical aggregation path. Existing Event and Unit reads do not jointly
provide the batched public presentation details needed for compact linked
history rows.

## Existing Contract

- Statistics exposes query-time Ranker, Commander, General, Event Battle,
  Unit-performance, attendance, and Leaderboard reads. Role summaries are
  grouped by Player and Unit type, not Event.
- Events exposes canonical Event identity/time to Statistics; its current
  contract does not define the batch Event presentation read needed by the
  profile.
- Units exposes hierarchy identity/subtree reads to Statistics; its current
  contract does not define the batch Unit presentation read needed by the
  profile.
- Players exposes cached Roblox username/headshot metadata in a batch read.
  Canonical identity and fallback behavior remain unchanged.

## Missing Capability

1. A Statistics-owned public read for one stable game Player ID, requested
   Statistics window, and optional supported Unit type, returning canonical
   Player/Commander/General summaries and per-Event detail.
2. Batch public Event and Unit presentation reads for Event labels/details and
   Unit identity/icon data without per-row queries.

## Proposed Change

- Add an additive Statistics Player-profile read. It accepts a stable game
  `playerId`, existing Statistics window, and optional canonical Unit-type
  filter; returns role-specific summaries and deterministic newest-first
  detail rows derived from the existing current-effective-finalized-Audit
  source. Statistics continues to own all aggregation, ratios, filters, and
  zero-denominator behavior.
- Add only the Events- and Units-owned batch presentation reads required for
  Event and Unit labels/navigation imagery. The profile consumer batches unique
  IDs; neither Statistics nor React reads producer persistence directly.
- Bound or paginate detailed rows without truncating full-window summaries.
  Event result/win-loss is not inferred; General type distribution is preserved
  rather than hidden behind a misleading type filter.
- Keep Players identity presentation, all source schemas, memberships, Event
  and Audit records, and existing metric semantics unchanged.
- Update the relevant module contracts, source manifests, discovery registry,
  tests, and changelogs.

## Alternatives Considered

- Derive metrics or ratios in the page: rejected because Statistics owns those
  semantics.
- Filter only the displayed rows on the client: rejected because summaries
  would no longer describe the visible data.
- Perform Event/Unit lookups separately for each row: rejected due to N+1
  query behavior.
- Read neighboring modules' persistence directly: rejected because it bypasses
  producer ownership and public contracts.
- Persist summary/history aggregates: rejected; existing source records are
  sufficient and no schema or cache change is needed.
- Infer Event victory/defeat from side colors or metric values: rejected
  because the Player-relative result is not established by this read.

## Affected Consumers

- Public route `/players/[id]` and its Statistics-owned presentation.
- Event/Unit profile-row links and their tests.

## Compatibility / Risk

The change is additive and query-time. Existing readers, callers, stable IDs,
profile URLs, identity fallback, persisted data, and metric semantics remain
unchanged. No migration is required. Public DTOs expose only existing public
Event/Unit presentation and finalized Statistics results. Main risks are
incorrect aggregation/filter consistency and history query cost; tests must
cover summary/detail equivalence, deterministic ordering, batch lookup counts,
and bounded detail with complete summaries.

## Approval Decision

Approved for the bounded additive Statistics Player-profile read and the
minimum Events/Units-owned batch presentation reads required by the public
profile. Statistics remains authoritative for all calculations and filtering;
Players remains authoritative for Player identity; Events and Units remain
authoritative for their public presentation. No schema migration, persisted
aggregate, change in ratio/window/type semantics, or inferred Event outcome is
approved.

## Decision Owner

The human requester.

## Result

Implemented under TKT-20261103-000053-001. Added the Statistics-owned Player
profile read, Events- and Units-owned batch presentation reads, and the public
profile composition without schema changes. The test suite, lint, type-check,
production build, and `git diff --check` passed; browser QA confirmed filter
behavior and no page-level horizontal overflow at 390, 768, 1024, 1440, and
1920 pixel viewport widths.
