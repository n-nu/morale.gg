# ADR-20260930-009: Development-Only Demo Sign-In and Fresh-Database Root Bootstrap

- Status: Accepted
- Date: 2026-09-30
- Related ticket: TKT-20260930-000040-001
- Human approval: Requested and approved by the product/architectural owner on 2026-09-30 (Milestone 1 grading-access fix)

## Context

Authentication is Auth.js Google OAuth with database-backed sessions. A fresh
clone could not reach authenticated management surfaces without private Google
OAuth credentials or a new Google Cloud project, a manual `User.id` lookup for
`ROOT_UNIT_COMMANDER_USER_ID`, and `npm run db:seed`. `npm run demo:reset`
refused an empty database, and seeded demo identities had no way to sign in.
A grader needs a safe local path that does not weaken production
authentication.

## Decision

1. **Fresh-database bootstrap.** When `npm run demo:reset` (already restricted
   to non-production, loopback, configured Compose databases) finds zero
   RootUnits, it creates the fixture User `demo-user-root-commander`, the root
   Unit `root-morale-gg`, its RootUnit designation, and the matching level-0
   membership, then performs the normal reset. Existing databases with one
   RootUnit keep their existing Commander unchanged.
2. **Development sign-in.** `/dev/sign-in` and its server action create an
   ordinary Auth.js database `Session` row plus the standard non-secure
   `authjs.session-token` cookie for a chosen seeded demo identity. It is
   enabled only when **both** `NODE_ENV === "development"` (i.e. `next dev`)
   **and** `DEV_SIGN_IN_ENABLED === "true"`. Production builds (`next start`)
   return 404 for the page and the server action refuses to run.
3. **Fixed allowlist.** Only the seven fixed demo identity IDs in
   `src/lib/demo-identities.ts` can be selected; arbitrary or real
   Google-linked User IDs are rejected. The identity must already exist.
4. **No authority shortcut.** Dev sign-in grants no permissions. Each demo
   identity has only the Unit/Event authority seeded by the demo reset, and all
   server-side authorization checks are unchanged. Website-administrator
   allowlisting is not involved.

## Consequences

- A grader can clone, copy `.env.example`, migrate, run `demo:reset`, run
  `npm run dev`, and sign in at `/dev/sign-in` without Google credentials.
- Google OAuth remains the only production sign-in method; `auth.ts` is
  unchanged.
- `.env.example` enables the flag for local convenience; it has no effect
  outside `next dev`.
- Development sessions assume an HTTP origin (`authjs.session-token`); running
  `next dev` behind HTTPS would require the `__Secure-` cookie name and is not
  supported.
