# ADR-20260927-007: Derived Statistics Over Effective Finalized Audits

- Status: Accepted
- Date: 2026-09-27
- Related ticket: TKT-20260927-000024-001
- Human approval: Approved by the human architectural owner on 2026-09-27

## Context

morale.gg now has immutable finalized Audit results, Player result rows and
roles, historical UnitMembership, persistent Unit hierarchy, Event dates, and
strict Event command groups. Statistics must expose public Ranker, Commander,
General, persistent Unit, and attendance results without becoming a competing
source of gameplay history.

The MVP permits one finalized Audit per atomic Event unit, but future Audit
amendments will preserve superseded history. Audits owns the semantic
determination of the current effective finalized Audit for an atomic Event unit
and exposes that decision through `audits-statistics-effective-finalized-audit`.
Statistics consumes that seam and does not reproduce Audit lifecycle or future
supersession predicates. Events owns canonical Event occurrence time and its
normalization; Statistics owns the common window policy and applies it to that
Event-owned time. Raw-population aggregation prevents double-counting, blending
incompatible Unit types, or averaging already-aggregated averages.

## Decision

Create a dedicated read-derived `statistics` module. It owns the trailing
14-day (default), trailing 30-day, and all-time window policy, aggregation
semantics, derived metric calculations, and public Statistics query/read
services. It consumes the Audits-owned effective-finalized-Audit decision and
the Events-owned canonical, normalized occurrence time; it owns neither
decision. It owns no authoritative history, mutable aggregate tables, roster
membership, Unit hierarchy, Event dates, participation, command groups, or
Audit persistence.

Statistics applies its trailing 14-day (default), trailing 30-day, and all-time
windows to the canonical Event occurrence timestamp supplied by Events after
Events-owned normalization. The same Statistics window policy and
Audits-owned effective-finalized-Audit seam are used by Ranker, Commander,
General, Unit, and attendance queries. Audit creation, draft, finalization,
correction, and supersession timestamps are not window inputs, and Statistics
does not reproduce Audit lifecycle or supersession predicates.

All metric paths aggregate raw observations and preserve numerator/denominator
populations. KDR is pooled kills/deaths, not a sum or average of KDR values.
Zero deaths preserve a zero denominator and use the approved display form
(`kills K` or `kills+assists K+A`) rather than pretending to be an ordinary
numeric ratio.

Ranker observations include every Player result in an effective finalized Audit,
including mercenaries and never-rostered Players. Distinct Event counts dedupe
multiple atomic Audits from one Event per Player. Commander observations use
only the battlefield Commander role, not persistent Unit Commander status.
General observations require a designated Commander and at least two unique
flattened descendant atomic units; mixed Unit types remain separate combat
populations. Persistent Unit results expose Direct Performance, Organizational
Performance, and equal-weight Average Unit Performance as distinct views.
Attendance is Player + persistent Unit + Event, derives roster eligibility from
Event-date membership, creates one obligation when any mandatory atomic unit
exists, and distinguishes PRESENT, ABSENT, and PENDING. Pending obligations do
not enter resolved attendance percentages. Mercenary appearances never create
or satisfy roster obligations.

All MVP Statistics are public by game Player/Unit identity. Auth.js submitter
identity is not exposed merely because it created an Audit. MVP computation is
query-time indexed PostgreSQL aggregation with no mutable Statistics tables,
cache, materialized view, scheduled job, or incremental counters.

## Alternatives

- Store mutable Player/Commander/General/Unit statistics tables: rejected as a
  competing source of truth and a correction/supersession risk.
- Let each query select finalized Audits independently: rejected because future
  supersession and effective-history semantics would drift.
- Use Audit timestamps for windows: rejected because Event occurrence time owns
  the temporal meaning.
- Combine mixed Unit types into one General combat number: rejected because the
  populations are not compatible.
- Average child/group or parent/child summaries: rejected because it creates
  recursive averages-of-averages and unequal Unit weighting.
- Create attendance from Audit appearances alone: rejected because obligations
  depend on Event-date UnitMembership and mandatory atomic-unit state.

## Consequences

Positive consequences are consistent metric semantics, preserved history,
correct mercenary and roster attribution, and a future-compatible supersession
seam. The query-time approach avoids MVP synchronization jobs and duplicate
truth.

The design requires documented read contracts from Audits, Events, Players, and
Units. Audits determines which finalized Audit is currently effective; Events
determines and normalizes canonical occurrence time; Statistics determines
window inclusion. Exact DTO shape, SQL decomposition, and indexes remain
implementation choices after approval, but they must support the stated access
paths and retain raw numerators/denominators.
