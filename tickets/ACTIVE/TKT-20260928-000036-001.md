# Ticket: Development Demo Reset and Reseed

## Objective

Replace the namespace-only demo cleanup with an explicitly destructive, repeatable development reset that preserves the one existing RootUnit identity and its required Commander authentication identity, clears resettable domain data, seeds a coherent visual-review dataset using current Prisma invariants, and verifies seeded relationships and application readers. Do not modify Ticket 35 production code or domain behavior.

## Main Success Scenario

1. A developer runs `npm run demo:reset` against the configured local development database.
2. The command refuses production or ambiguous/remote database targets before mutation, reports safe host/name/environment/root details, and stops if RootUnit identity is not unique.
3. In one dependency-aware transaction, it clears resettable application/domain rows while retaining the exact RootUnit row and only required Commander authentication/bootstrap state.
4. It seeds realistic Units, Players, catalogs, authorization, Events, participation, Battle Structures, results, and Audits; verifies data and representative readers; and prints useful IDs and summaries.
5. A second run produces the same logical dataset without changing RootUnit identity or accumulating rows.
