# Ticket: Unit Statistics and Attendance Presentation

## Objective

Implement the public Unit Statistics and Player + Unit attendance presentation
using existing Statistics readers and the shared presentation foundation from
Ticket 29. Do not change Statistics semantics or create a new module.

## Main Success Scenario

1. A public visitor opens an existing Unit identity/detail route and selects a
   supported Statistics window.
2. The presentation renders Direct, Organizational, and Average Unit
   Performance as distinct perspectives, preserving Unit-type populations.
3. A Player + Unit view renders obligations and attendance states from the
   Statistics reader without exposing roster machinery or recalculating
   denominator semantics.

## Unit Statistics

Use existing Unit identity/detail routing. Render three clearly distinct
perspectives:

- Direct Performance: only the selected persistent Unit.
- Organizational Performance: selected Unit plus all descendants.
- Average Unit Performance: equal-Unit-weight additive/raw averages for
  qualifying Units; do not display averaged KDR.

Do not visually blur the perspectives together. Preserve Regular, Rifles,
Cavalry, and Artillery populations. If Direct has no observations while
Organizational has descendant observations, render the Direct empty state while
still rendering Organizational results.

## Attendance

Use existing Statistics-reader output for Player + Unit views: obligations,
present, absent, pending, and resolved attendance percentage.

- Zero obligations: show `No attendance requirement` or equivalent Not
  Applicable presentation, never 0%.
- Obligations exist with zero resolved observations: show `Pending` or `No
  resolved attendance yet`, never 0%.
- Pending remains visibly distinct from Absent.
- Resolved percentage is taken from Statistics; the UI does not recalculate
  denominator semantics.

Use existing public Player and Unit identities. Do not expose UnitMembership
machinery, authorization persistence, or Auth.js submitter identity.

## Shared Window and Traceability

Consume the shared Ticket 29 14 Days / 30 Days / All Time control. Do not create
a second component or policy. Where public identifiers permit, add lightweight
links from Unit Statistics to Events and finalized Audits/results. Do not add an
event-scoped Statistics query.

## States and Accessibility

Support no Unit Statistics, Direct-empty/Organizational-populated, no selected-
window observations, no attendance obligation, pending attendance, zero
resolved attendance, invalid Unit, and read/server failure. Reuse Ticket 29
responsive and accessibility patterns for mobile, tablet, and desktop.
