# Ticket: Ranker Integration Test Must Be Independent of Demo Data

## Objective

Correct the Ranker integration test's assumption that its four fixture Players
are the complete global Ranker result set. Determine and use the repository's
appropriate test-isolation strategy. The test must remain meaningful with or
without persistent demo data; do not weaken production Ranker behavior or add
a production-code workaround solely for test isolation.

## Investigation Context

This reliability defect was discovered incidentally while investigating Unit
Statistics and Player profile failures. Those failures came from the stale
Ticket 32 branch using the old EventCommandGroup shape; merging current
`main` resolved them. The Ranker test issue is separate and did not indicate
incorrect application aggregation. With the persistent seeded demo database,
the latest Ticket 37 verification returned 41 global results, including the
four intended fixtures and legitimate unrelated demo observations, instead of
the four rows assumed by the test. Do not modify PR #20 or Ticket 32; these
records may be referenced for investigation context only.

`src/modules/statistics/ranker.integration.test.ts` creates four uniquely
identified fixture Players, calls the public unfiltered
`getRankerStatistics` reader, then compares the complete global Player set to
those four fixtures. The public reader intentionally returns all qualifying
global observations; demo data makes the complete-set assertion invalid.

## Main Success Scenario

1. The integration test creates its Ranker observations using the repository's
   supported fixture/isolation mechanism.
2. It calls the real public Ranker reader and verifies the intended window,
   Event counting, type partitioning, totals, averages, and ratio semantics.
3. It proves each fixture Player is represented exactly once with the expected
   values without requiring unrelated global results to be absent.
4. The test passes on a database both with and without demo data and cleans up
   only data owned by its fixture.

## Isolation Strategy

Evaluate strategies in this order:

1. An isolated transaction/database fixture supported by the repository's
   test harness.
2. Scope the Ranker query using unique fixture identifiers/data only if the
   public API legitimately supports that scope; do not add a production filter
   solely for testing.
3. Assert on the uniquely created fixture Players and their expected
   aggregates, allowing unrelated global Players while checking fixture
   membership, uniqueness, and values exactly.
4. Use a repository-supported deterministic test reset/setup if it can be run
   safely and does not require the demo database to be empty.

The current reader accepts a window and time, not a Player filter or injected
database client, and the integration test calls the shared Prisma reader over
persisted finalized Audit sources. Therefore, first verify whether existing
test infrastructure can isolate the database/transaction without changing
production behavior. If not, use unique fixture identifiers and exact
fixture-scoped assertions: each expected fixture must occur exactly once and
match its expected aggregates; extra unrelated global Players are allowed.
Never silently ignore duplicate, missing, or wrong fixture results.

## Requirements

- Preserve the real Ranker reader and its all-global public semantics.
- Do not depend on the demo database being empty or reset it destructively as
  an implicit test precondition.
- Preserve assertions for intended default/14-day, 30-day, and all-time
  behavior, distinct Events, historical Unit type partitioning, finalized
  Audit selection, totals, averages, and ratio/zero-denominator semantics.
- Use isolated fixture state where supported; otherwise assert the exact
  created fixture Player set and values without asserting global result-set
  equality.
- Verify fixture results contain no duplicate fixture Player entries and do
  not silently tolerate missing, unexpected, or incorrect fixture aggregates.
- Ensure cleanup is bounded to records owned by this test fixture.
