# Ticket: Enrich Player identity with cached Roblox metadata

## Main Success Scenario

1. A manager enters a Roblox User ID in a Player registration or roster-add
   flow.
2. The server validates and resolves the ID through Roblox, then shows the
   verified Roblox username, avatar when available, canonical ID, and profile
   link before creating/reusing the Player and applying the requested
   membership operation.
3. Public Player-facing surfaces use the cached Roblox username/avatar or the
   canonical ID and neutral avatar fallback, while all persistence and
   navigation continue to use `Player.playerId`.

## Acceptance Criteria

- [x] `Player.playerId` remains the only canonical game Player identity; no existing foreign keys or public route keys change.
- [x] Add nullable cached Roblox username, avatar/headshot URL, and synchronization timestamp with a forward-only Prisma migration.
- [x] A Players-owned server-only Roblox service validates numeric IDs and response shapes, uses official batch-capable APIs, ignores Roblox display names, and accepts only documented Roblox avatar hosts.
- [x] New Player registration and roster-add flows resolve and display account metadata before manager confirmation; invalid IDs cannot create a Player through those flows.
- [x] Audit editor previews cached or Roblox-resolved identities for distinct IDs, requires manager confirmation for new IDs, and blocks finalization for invalid or temporarily unresolvable new IDs while allowing drafts and existing cached Players.
- [x] Existing Players are reused by canonical ID, with no duplicate Player or membership history mutation; Roblox outage preserves already verified cached data.
- [x] The Player directory, profile, roster, commander/Player identity surfaces, Event/Audit identity surfaces, Statistics/Leaderboard, Awards-associated Player presentation, and Player search use cached Roblox metadata or the ID fallback, never `Player.name` or Auth.js profile data.

- [x] Username/avatar fallback is `Roblox ID {playerId}` plus a neutral placeholder; profile links derive from `playerId`.
- [x] Set and document a 14-day stale-cache policy; normal page rendering never synchronously refreshes Players.
- [x] Provide an explicit, bounded, retry-safe, idempotent backfill command with batch API calls and summary counts; do not run it automatically.
- [x] Mocked tests cover Roblox valid/invalid/unavailable/malformed responses, username change, missing avatar, ID invariance, duplicate prevention, existing-cache failure, identity isolation, batch reads, and affected UI.
- [x] Update affected module manifests, contracts, registries, and changelogs as required by repository conventions.
