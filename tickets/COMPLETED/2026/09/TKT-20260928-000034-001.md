# Ticket: Event Battle Structure Domain and Manager Editor

## Objective

Implement the approved Event Battle structure domain and Event-manager editor,
including the authorized Ticket 34 review revision: compact creation into a
durable Unsorted state, a first-class visual tree organizer, authoritative
subtree moves, and one public read-only Battle Structure surface. Preserve the
existing Audit authority and result-history boundaries. Do not implement
Ticket 35 aggregation.

## Main Success Scenario

1. An Event owner or authorized Event manager opens the Event management Battle
   Structure editor.
2. The manager creates groups and atomic units using approved
  EventParticipations; new nodes persist with a nullable side and appear in
  the manager-only Unsorted bin.
3. Drag/drop or the accessible Move to fallback places nodes at a side root,
  in a compatible group, or back in Unsorted. Group moves update the entire
  subtree transactionally.
4. The server enforces same-Event, approved-participation, same-side,
  unassigned-parent, strict-tree, unique-descendant, cycle, and authority
  invariants.
5. A Unit Audit-authorized user discovers the exact claimed atomic unit in
   `/audits` without reselecting the Unit, while `canManageEvent` never grants
   Audit submission/finalization authority.
6. The public Event page presents assigned Defender and Attacker hierarchies
  in one Battle Structure section and omits Unsorted nodes.
7. Atomic Battle Details expose pending result and participating-player
  placeholders without reading draft Audit Player rows.
8. An eligible Event manager can record the initial Event result and the
   system retains immutable result history for a future correction workflow.

## Requirements

- Keep the durable battlefield side domain limited to `ATTACKER` and
  `DEFENDER`, with nullable `side` representing intentional `UNSORTED`
  configuration state as well as legacy unconfigured nodes. Do not add
  configurable side names or coalitions.
- Add optional validated Event attacker/defender image references using the
  existing image-reference behavior; no upload or object storage.
- Add AtomicEventUnit name and side, preserving its required
  `eventParticipationId` as the sole represented Unit claim. Keep mandatory
  state and Audit Unit type in the approved ownership location.
- Replace or supersede EventCommandGroup's descriptive Unit field with an
  authoritative approved EventParticipation foreign key, add side, and keep
  group commander as a Player fact. Do not retain two authoritative Unit IDs.
- Implement `events-audits-event-battlefield-management` using
  `canManageEvent(userId, eventId)`. Keep `canSubmitAudit` independent.
- Permit Event managers to create/configure/place/move/remove atomic units and
  groups, but keep Audits responsible for invariant validation and persistence.
- Creation does not require a side or parent. Unassigned groups cannot be
  attached beneath assigned-side parents; placement sets side from the target.
- Enforce same Event, approved participation, same-side parent/child, no
  cycles, one immediate parent, unique atomic contribution, unique flattened
  descendants, and existing General qualification semantics server-side.
- Moving a group across sides or to Unsorted updates all descendant groups and
  atomic units in one authorized transaction; no mixed-side subtree is left.
- Public Battle Structure reads include only assigned-side roots and nodes;
  Unsorted configuration state is manager-only.
- Embed the compact Battle Structure organizer in Event management. Keep
  creation forms collapsed, make drag/drop primary, and retain a compact
  accessible Move to fallback.
- Public Event detail uses one Battle Structure section, removes the separate
  Command Structure affordance and duplicate placeholder, and renders atomic
  Battle Details / Unit Statistics / Participating Players placeholders only.
- Do not implement Ticket 35 aggregation or expose draft Audit Player rows.
- Provide drag/drop plus accessible `Move to...` fallback without authoritative
  client-only optimistic mutations.
- Add `/audits` discovery filtered to atomic units whose represented Unit is
  authorized for the current user through existing `canSubmitAudit`. Do not
  require Unit reselection or expose unrelated atomic units.
- Add immutable Event result/revision persistence with effective-result
  cardinality, `ATTACKER_WIN | DEFENDER_WIN | DRAW`, initial result eligibility
  after scheduled time, and manager authorization through `canManageEvent`.
- Preserve every prior effective result. A currently authorized Event manager
  may propose a different correction, but only another currently authorized
  Event manager may approve or reject it. Proposers cannot review their own
  proposals, including as owner; single-manager corrections remain pending.
- Define a safe legacy state for Events/structures without explicit sides;
  never infer sides from participating Units or ordering.
- Do not add historical Rank fields or pre-battle Commander semantics.

## Acceptance Criteria

- [x] Assigned-side and hierarchy invariants are server-validated, including
  rejection of cycles, foreign-Event moves, and invalid parentage.
- [x] Approved participation is required for group and atomic claims, and
      foreign/requested/denied/arbitrary Units are rejected.
- [x] Event managers can manage structure through `canManageEvent`; Unit
      Audit users cannot manage Event structure through `canSubmitAudit`.
- [x] `/audits` discovers only relevant atomic units through the represented
      participation Unit and existing Audit authority.
- [x] Initial Event result accepts only the three approved values and only
      after the Event is concluded by existing scheduled-time semantics.
- [x] Result history is immutable and has at most one effective result.
- [x] Correction proposals require a different currently authorized Event
  manager for approval/rejection; proposer self-review and owner bypass are
  rejected, and single-manager corrections remain pending.
- [x] Legacy Events remain valid and render an explicit unconfigured-side
      state until a manager assigns sides.
- [x] No production Statistics aggregation is added; the existing public
  structure DTO is filtered, and no metrics DTO is introduced.
- [x] New atomic units and groups are created Unsorted without a side/parent
  field and appear in a manager-only Unsorted bin.
- [x] Root, nested, cross-side subtree, and Unsorted moves persist through the
  authoritative server mutation; invalid hierarchy targets are rejected.
- [x] Move to fallback performs the same allowed moves as drag/drop.
- [x] Public Event renders one side-separated Battle Structure tree and no
  Unsorted nodes or management controls.
- [x] Atomic Battle Details and player/statistics placeholders are present;
  no Ticket 35 result aggregation or draft-player data is exposed.
- [x] Responsive organizer is usable at 390px, 768px, and 1440px.
- [x] Browser walkthrough covers create, organize, reassign, fallback, reload,
  and public visibility for the requested workflows.
- [x] Focused domain/authorization/migration tests, Prisma validation and
