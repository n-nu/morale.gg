# Ticket: Statistics Foundation and Ranker Statistics

## Objective

Implement the approved Statistics source-contract operations in their owning
modules, the shared query-time Statistics window/ratio/query foundation, and
public Ranker statistics. Audits owns effective-finalized-Audit selection and
raw observation reads; Events owns canonical Event occurrence time and its
normalization; Statistics consumes those operations and owns window policy and
derived metrics. Preserve all metric semantics approved by Ticket 24. Do not
implement Commander, General, persistent Unit statistics, attendance, or
UI/leaderboard integration.

## Dependencies

- `TKT-20260927-000024-001` is COMPLETED; its architecture is approved.
- `ADR-20260927-007` is Accepted and `BCR-20260927-005` is Approved.
- The four Statistics source contracts are stable and registered.

## Main Success Scenario

1. A public reader requests Ranker statistics for an approved window.
2. Statistics applies the shared window policy to Events-owned canonical,
   normalized Event occurrence time.
3. Statistics obtains only current effective finalized Audit observations
   through the Audits-owned source contract.
4. The result includes all eligible Player observations and distinct Event
   participation counts without changing authoritative source records.

## Requirements

- In Audits, implement the approved effective-finalized-Audit operation and
  common raw observation reads required by Statistics. Include the approved
  command-group descendant source data for later General statistics. Audits
  owns current-effective determination; do not add future supersession behavior
  or duplicate Audit lifecycle predicates in Statistics.
- In Events, implement the approved canonical Event-time source operation,
  returning Events-owned canonical occurrence time according to the contract,
  including Events-owned normalization. Events does not select Statistics
  windows or decide inclusion.
- In Statistics, implement one shared window policy: trailing 14 days by
  default, trailing 30 days, and all time. Apply it to canonical Event time
  returned by Events. Never use Audit timestamps or reproduce Event-time
  normalization.
- For each Player and each window (14-day default, 30-day, all time), report
  total kills, deaths, and assists; pooled KDR; pooled (K+A)/D; average kills,
  deaths, and assists per Audit appearance; and distinct Events participated.
- Keep combat measures partitioned by Regular, Rifles, Cavalry, and Artillery.
  Deduplicate distinct Event participation once per Player/Event across the
  included atomic Audits.
- Preserve the approved zero-death representation: retain the zero denominator
  and display the kill numerator for KDR and the kills-plus-assists numerator
  for (K+A)/D, not an ordinary numeric ratio.
- Implement public Ranker observations for all Player result rows, including
  mercenaries, Players rostered elsewhere, and never-rostered Players.
- Use query-time PostgreSQL aggregation and documented source contracts only.
- Keep all statistics public and keyed to game Player identity, not Auth.js
  submitter identity.
