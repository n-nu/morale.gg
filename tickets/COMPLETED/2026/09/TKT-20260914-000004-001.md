# Ticket: Establish Units Module and Public Unit Hierarchy

## Implementation Owner

Aiden Slabiak

## Objective

Establish the first product-domain module for morale.gg using the existing persisted `Unit` representation.

This ticket creates the Units module and implements public, read-only browsing of the organizational hierarchy. The purpose is to establish a stable Unit identity/hierarchy capability that later Player, Membership, EventParticipation, permissions, and Audit work can build against.

This ticket does NOT authorize changes to the Unit schema, unit ownership, permissions, invites, creation, Player identity, memberships, rosters, Events, EventParticipation, Audits, or statistics.

## New-Module Exception

This ticket explicitly authorizes creation of the first `units` module. `MODULE.md` does not yet exist for this module, so per `AGENT_WORKFLOW.md` Section 5 (New-Module Exception), its absence is not a blocking condition. Developer A must:

1. Read `docs/templates/MODULE_TEMPLATE.md`.
2. Read `docs/SYSTEM.md`, `BACKLOG.md` (US-03, US-05), and `docs/architecture.md`.
3. Define the module's initial purpose, ownership, non-ownership, and public boundary (see Module Responsibilities below).
4. Create `src/modules/units/MODULE.md`.
5. Register the module in `docs/registry/MODULES.yaml`.
6. Create only contracts justified by an actual cross-module consumer (none currently exists — see Contracts section below).

1. An unauthenticated visitor opens the Units area.
2. Existing Units are displayed.
3. The seeded root Unit is visible.
4. The visitor opens a Unit.

9. Repeated navigation supports hierarchy deeper than one level.
