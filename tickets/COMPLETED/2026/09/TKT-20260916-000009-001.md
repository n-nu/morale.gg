# Ticket: Development-Only Authentication Diagnostic Page

## Implementation Owner

Agent-assisted (developer tooling).

## Objective

Provide a small, development-only diagnostic page that lets a developer
manually verify the full authentication flow: Google sign-in through Auth.js,
resolution of the authenticated `User.id`, and evaluation of the existing
`isCurrentUserWebsiteAdmin()` capability from `src/lib/website-admin.ts`
(implemented under TKT-20260915-000008-001, now `COMPLETED`).

This is developer tooling only. It is not an MVP admin interface, does not
create any new authorization mechanism, and does not modify database state.

Ticket 8 was already `COMPLETED` at the time this need was identified, so this
work is tracked under its own ticket rather than reopening or silently
expanding Ticket 8.

## Main Success Scenario

1. A developer starts the local application in development mode.
2. The developer visits `/dev/auth-diagnostic` while signed out and observes
   `Authenticated: NO` and `Website administrator: NO`.
3. The developer signs in through the real Google/Auth.js flow.
4. The developer revisits `/dev/auth-diagnostic` and observes `Authenticated:
   YES`, the authenticated `User.id`, and the current website-administrator
   result derived from existing bootstrap configuration.
5. The developer configures `WEBSITE_ADMIN_USER_IDS` locally using the
   displayed `User.id`, restarts, and observes `Website administrator: YES`.
6. In a production build/runtime, the same route is unavailable.

## Verification

- Command/check: `npm run dev`, then visit `http://localhost:3000/dev/auth-diagnostic`
  signed out, then signed in via Google, then with `WEBSITE_ADMIN_USER_IDS` set
  to the displayed `User.id`, then unset/mismatched.
- Expected result: signed out shows `Authenticated: NO` / `Website
  administrator: NO`; signed in and unconfigured shows `Authenticated: YES`,
  the `User.id`, and `Website administrator: NO`; signed in and configured with
  a matching ID shows `Website administrator: YES`; `npm run build` followed by
  `npm start` returns 404 for the same route.
- Actual result: executed by the developer on 2026-09-16 with real Google
  OAuth credentials, using the assistant's browser tooling to drive the
  interactive steps.
  - Signed out: `Authenticated: NO`, `Website administrator: NO`.
  - Signed in via real Google account, `WEBSITE_ADMIN_USER_IDS` unset:
    `Authenticated: YES`, a stable User ID was displayed, and `Website
    administrator: NO`.
  - `WEBSITE_ADMIN_USER_IDS` set to the matching displayed `User.id`:
    `Website administrator: YES`.
  - `WEBSITE_ADMIN_USER_IDS` set to a non-matching value: `Website
    administrator: NO`.
  - `WEBSITE_ADMIN_USER_IDS` unset again: `Website administrator: NO`.
  - `npm run build` followed by `npm start`: `GET /dev/auth-diagnostic`
    returned `404 This page could not be found.`
  All results matched expectations; no deviation observed.
