# Ticket: Player Statistics Presentation and Shared Public Statistics UI

## Objective

Implement the shared MVP Statistics presentation foundation and public Player
Statistics experience using the existing Statistics public readers and DTOs.
Do not create a new module or change Statistics calculation semantics.

## Main Success Scenario

1. A public visitor opens `/statistics` or a Player profile without signing in.
2. The presentation passes the selected 14-day, 30-day, or all-time window to
   Statistics readers and renders approved Ranker, Commander, and General
   results without recalculating them.
3. The visitor can understand type partitions, zero-death ratios, partial/no-
   data states, and trace results to public Event/Audit history where IDs exist.

## Shared Presentation Scope

- Add the public `/statistics` landing/discovery route.
- Add the active global `Statistics` navigation entry.
- Provide one reusable keyboard-accessible 14 Days / 30 Days / All Time control,
  defaulting to 14 Days. Pass its value to Statistics readers; calculate no
  date boundaries in UI code.
- Provide reusable rendering for existing ratio DTOs, including approved
  zero-death `K` and `K+A` forms.
- Provide reusable textual Unit-type presentation for Regular, Rifles,
  Cavalry, and Artillery.
- Provide common loading, empty, invalid, and read-error presentation where
  practical.
- Keep `/statistics` as simple navigation toward Players, Units, and
  Events/history; do not turn it into a score-based leaderboard.

## Player Profile

Use the existing Player identity route and stable game PlayerID. Do not require
current UnitMembership. A safely exposed Unit-local alias may be shown; do not
invent a global canonical name. Fall back to displaying PlayerID.

### Ranker

Render Statistics-reader output for Kills, Deaths, Assists, KDR, (K+A)/D,
average Kills/Deaths/Assists per Audit appearance, and distinct Events
participated. Preserve Regular/Rifles/Cavalry/Artillery partitions. Do not
compute values in components.

### Commander

Render only when observations exist: battles commanded, total K/D/A, pooled
KDR, Tickets, Flag Captures, Flag Losses, Stars, averages for those measures,
and average Player count. Preserve type partitions. Persistent Unit Commander
status must not affect eligibility.

### General

Render only when observations exist: qualifying groups commanded, distinct
Events commanded, total atomic units commanded, and Regular/Rifles/Cavalry/
Artillery atomic-unit counts. Keep combat/result sections separated by Unit
type; do not display mixed-type General KDR.

### Partial and Traceability States

Support Ranker-only, Ranker plus Commander, Commander without General, all
sections, no observations in the selected window, Player without Statistics,
invalid Player, and Statistics read failure. Do not render zero-filled sections
when no observations is the actual state.

Where existing public DTOs and routes provide identifiers, add lightweight
links to Events, finalized Audits/results, and command structures. Do not query
private persistence merely to manufacture links. Event-specific Statistics
calculation remains out of scope.

## Responsive and Accessibility Requirements

Support mobile, tablet, and desktop using semantic headings, readable cards or
tables, keyboard-accessible controls, and textual labels that do not depend on
color. Do not perform a broad site redesign.
