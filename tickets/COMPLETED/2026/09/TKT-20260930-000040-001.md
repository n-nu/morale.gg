# Ticket: Development-only demo sign-in for grading access

## Main Success Scenario

1. A TA clones the repository, runs `npm ci`, copies `.env.example` to `.env`, starts Compose PostgreSQL, generates the client, deploys migrations, and runs `npm run demo:reset` on an empty database.
2. The reset bootstraps a development RootUnit and Commander User when no RootUnit exists, then seeds the demo world.
3. The TA runs `npm run dev`, opens `/dev/sign-in`, chooses a seeded demo identity, and reaches the authenticated management surfaces with that identity's seeded authority.
4. Under `next start`/production, `/dev/sign-in` returns 404 and its server action refuses to create sessions; Google OAuth remains the only production sign-in.

### Result

Added a development-only `/dev/sign-in` that creates standard Auth.js database sessions for a fixed allowlist of seeded demo identities, gated on `next dev` plus `DEV_SIGN_IN_ENABLED="true"`. `npm run demo:reset` now bootstraps the RootUnit and a fixture Commander on an empty database, so a fresh clone needs no Google credentials, User ID lookup, `db:seed`, or admin configuration.

### Deviations and Known Limitations

- `npm run db:seed` on an empty database likely fails (circular immediate FKs between `Unit` and `RootUnit`); not in the grading path and left unchanged.
- Dev sign-in assumes an HTTP origin (`authjs.session-token` cookie name).
- `next start` locally logs Auth.js `UntrustedHost` without `AUTH_TRUST_HOST`/`AUTH_URL`; pre-existing and unrelated.
