# Ticket: Verify shared backend foundation against PostgreSQL and Google OAuth

## Objective

Verify the completed shared backend foundation end-to-end against real PostgreSQL and Google OAuth dependencies. This ticket records verification only; it does not authorize architecture changes, product features, backend implementation changes, dependency upgrades, or repairs to discovered defects.

## Main Success Scenario

1. A clean PostgreSQL development database is available and configured without committed secrets.
2. The existing Prisma migration applies and Prisma reports the schema as valid/current.
3. The existing seed creates exactly one unparented root Unit, no Player, and remains idempotent on a second run.
4. The Next.js application and existing server-side Prisma boundary can read and write PostgreSQL using temporary controlled verification data that is cleaned up.
5. Google sign-in completes through the existing Auth.js route, persists one User and its Account, creates a database-backed Session, resolves the authenticated identity server-side, and creates no Player.
6. Sign-out invalidates the active session, and signing in again with the same Google identity reuses the existing User without duplication.
7. Installation, Prisma validation/generation, lint, type check, production build, and npm audit review are complete.
8. The ticket records PASS, FAIL, or ENVIRONMENT-BLOCKED for every verification area and routes any implementation defect to a separate follow-up.
