# Ticket: Shared backend foundation architecture and implementation

## Objective

Establish the minimum shared persistence and authentication foundation required by the
morale.gg MVP, using the repository's planned Next.js, Prisma, PostgreSQL, and Google
authentication direction. The backend topology and the additional authentication and minimal
schema decisions are approved by the human architectural owner. Implementation remains limited
to the approved foundation scope.

This ticket does not authorize UI feature work, authorization policy, child-unit invites,
roster workflows, event workflows, audit workflows, statistics, or a separate backend
service.

## Main Success Scenario

1. The human architectural owner approves the proposed Next.js server-side application-layer topology.
2. The implementation establishes PostgreSQL connectivity, Prisma migrations and seed
   workflow, Google website authentication, and persistent `UserAccount` resolution.
3. Future server-side Units, Players, Events, Participation, and Audit work can use the
   shared persistence and identity foundation without independently inventing infrastructure.

## Approved RED Decisions

- Auth.js/NextAuth with Google OAuth, the Prisma adapter, and database-backed sessions is
  approved for this ticket.
- The minimal foundation schema may include Auth.js persistence models and only a stable-key,
  named, optional-parent `Unit` representation with timestamps where appropriate.
- The seeded root `Unit` has no parent.
- `Player`, membership, invite, permission, event, participation, audit, and audit-detail models
  are explicitly deferred to their owning module tickets.
- Final Unit ownership and permission behavior is explicitly deferred.

### Deviations and Known Limitations

- The Unit representation is intentionally incomplete and must not be treated as the final Unit
  domain schema.
- Detailed persistent schema design beyond the approved Auth.js models and minimal Unit remains
  unresolved. Any relationship cardinality, ownership, permission, public contract, historical
  representation, or module boundary required later must be classified and approved before it is
  encoded.
- No Player is created automatically when an Auth.js `User` authenticates.
- PostgreSQL-backed migration, seed, read/write, and Google OAuth smoke verification remain
  environment-dependent because no local PostgreSQL server or OAuth credentials were available.
- A clean `npm ci` was not completed because Windows held a native `lightningcss` file open;
  `npm install` restored dependencies successfully.
