# Ticket: Refine public Event results and statistics

## Main Success Scenario

1. A visitor opens an Event with a finalized result and sees a restrained,
   accessible winner/loser/draw treatment.
2. The visitor compares sides using a single clear Unit statistics
   presentation, with totals primary and per-player averages secondary.
3. The visitor expands participating structure/player information without
   encountering duplicate Company statistics.

## Acceptance Criteria

- [x] Effective attacker win, defender win, and draw have subtle, distinct
      side/result treatments and concise non-color labels.
- [x] No conclusion has no result label, badge, tint, or conclusion placeholder.
- [x] The public Unit statistics presentation orders columns as Player Count,
      Kills, Deaths, Assists, K/D, Flag Captures, Flag Losses, Stars.
- [x] Per-Company average Kills/Deaths/Assists are displayed secondarily using
      finalized Player appearances as denominator, including zero values.
- [x] Side summaries prioritize Tickets, pooled K/D, and Flag Captures, in
      that order; Tickets receives slightly greater emphasis.
- [x] Company statistics are not repeated inside the participating
      player/structure disclosure; useful structure, Unit links, and Player
      results remain accessible.
- [x] Battle Structure remains readable and primarily structural.
- [x] Local horizontal scrolling, where needed, does not cause page-level
      overflow at 390, 768, 1024, 1440, and 1920 pixel viewports.
- [x] The Event Battle DTO/contract addition is additive and query-time;
      existing result, finalized-Audit, Ticket, K/D, flag, Stars, Unit,
      Player-count, and relationship semantics remain unchanged.
- [x] No schema migration or manager-page change is made.
- [x] Focused result-state, ordering, average, summary, disclosure, and reader
      tests pass; browser checks cover representative viewports.
