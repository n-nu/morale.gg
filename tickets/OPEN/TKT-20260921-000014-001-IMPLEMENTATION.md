## What was implemented

### Persistent Players

- Added a `Player` model with an internal database ID, unique external game `playerId`, display name, and creation/update timestamps.
- Kept Players independent of Auth.js website Users and Unit authority.
- Added authenticated registration with validation and safe duplicate-ID rejection.
- Added lookup by name or game ID so existing Players can be reused.
- Game IDs remain case-sensitive text, preserving leading zeroes. Surrounding whitespace is trimmed; embedded whitespace/control characters and IDs over 128 characters are rejected. Names are trimmed and limited to 100 characters.

### Memberships and rosters

- Added `UnitMembership` records with start and optional end timestamps.
- Current rosters derive from memberships with no end timestamp.
- Ending a membership preserves the Player and historical membership record.
- Rejoining creates a new membership period; a Player can belong to multiple Units.
- Added a PostgreSQL partial unique index to prevent duplicate active Player/Unit pairs, including concurrent additions.
- Added restrictive foreign keys and a check preventing an end timestamp before the start timestamp.
- Membership additions and endings run transactionally. Conditional updates safely reject concurrent double removals.

### Authorization

- Registration requires a server-resolved authenticated session.
- Every roster add/end uses the existing Units-owned `canManageRoster(userId, unitId)` capability before writing.
- Client-provided authority identities are not trusted.
- Missing targets, mismatched Unit/membership targets, unauthorized changes, duplicate active memberships, and already-ended memberships fail safely.
- No Units authority internals or new permission semantics were introduced.

### Application UI

- `/players`: public search and authenticated registration, with validation feedback.
- `/players/[id]`: Player identity and active/ended membership history.
- `/units/[unitId]`: current roster, Player detail links, and add/end controls for authorized managers.
- Added pending form states and Player error/not-found pages.
- Preserved the existing Unit hierarchy presentation. Demo Units intentionally have no persistent roster or mutation controls.
