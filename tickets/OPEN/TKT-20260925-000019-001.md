# Ticket: Event Sides and Participation Team Assignment

## Implementation Owner

Developer B — Chandler Lovely (GitHub: ChanMan64)

## RED Approval Required

This ticket adds two persistent fields — `Event.hostSide` and
`EventParticipation.team` — which changes Ticket 15's approved
EventParticipation shape and the Event model. Under `AGENT_WORKFLOW.md`
Section 10 this is a RED change: **its pull request is the escalation
artifact, and merging requires the Lead's explicit approval.** The feature
was reviewed with the Lead in person on 2026-09-25 against a working local
demonstration; this PR formalizes it.

## Objective

Make an event's two sides first-class and publicly legible: creation names
the participating countries (host side and, via the existing `opponent`
field, the opposing side); event managers assign each approved unit to a
side; the public event page shows the sides as a versus panel. Guests can
finally see who fights whom without interpreting a free-text opponent label.

## Main Success Scenario

1. An authorized creator names two sides on the create form (optional,
   restricted to the defined nation list, blank entry to clear).
2. A unit requests participation (Ticket 15 path, unchanged).
3. A manager approves the request and assigns a side, offered from the
   event's declared sides plus sides already in use; denial stores no side.
4. The public event page shows approved units grouped under their sides in
   a versus layout; pending and denied stay management-only.
5. Terminal-transition, concurrency, and authorization behavior from
   Ticket 17 is unchanged.
