# Ticket: Event Battle Statistics Read and Public Presentation

## Objective

Implement the approved public Event Battle read seam and presentation over the
Event Battle structure. Statistics owns all derived metrics; Events presents
the returned DTO and authoritative Event result without querying Audit data.

## Main Success Scenario

1. A public visitor opens an Event with configured battlefield sides.
2. Events requests `getEventBattleStatistics(eventId)` from Statistics.
3. The compact Battle section presents Defender and Attacker hierarchy with
   atomic summaries, pending/finalized states, and the current Event result.
4. The visitor expands an atomic unit to see position, Player identity or safe
   Unit-local alias, K/D/A/KDR, and secondary finalized metrics.

## Requirements

- Add the Statistics-owned Event-scoped reader and consume only approved
  source seams; Event UI must not aggregate Audits.
- Return atomic identity/name, side, participation-backed Unit display, Audit
  type, finalized/pending state, effective Audit Commander, K/D/A, approved
  zero-death KDR, Tickets, Flag Captures, Flag Losses, Stars, and expanded
  Player result rows.
- Resolve a Unit-local alias only where safely available for the represented
  participation; otherwise display stable public PlayerID. Never invent a
  canonical global Player name.
- Omit historical Rank-at-Event entirely.
- Keep groups organizational by default. Optional aggregates must use unique
  flattened atomic descendants, raw populations, and existing type semantics;
  never recursively average ratios, double-count nested units, or merge
  incompatible Audit types.
- Present the public Battle layout with Defender and Attacker columns on
  desktop, accessible stacking/selection on narrow screens, compact groups
  and atomic rows by default, and progressive disclosure for Player rows and
  secondary finalized metrics.
- Apply no-result normal side styling; apply readable victory/defeat/draw
  treatments only from the authoritative Event result.
- Present `Battle sides not configured` for legacy Events rather than infer a
  side. Keep pending Audit data safe and do not expose private drafts or
  authorization details.

## Acceptance Criteria

- [ ] `getEventBattleStatistics(eventId)` returns the approved atomic and
      Player DTO fields with no private persistence leakage.
- [ ] KDR and all metric aggregation use Statistics-owned raw semantics and
      approved zero-death behavior.
- [ ] Pending/finalized states and Event result states are distinct and
      truthful; no outcome is inferred from metrics.
- [ ] No Rank column or current Rank substitute appears.
- [ ] Group descendants are unique and no recursive average-of-averages or
      type merging occurs.
- [ ] Desktop/mobile public Battle layout is accessible, progressively
      disclosed, and has no page-level horizontal overflow.
- [ ] Focused Statistics/source/presentation tests, applicable existing
      regressions, lint, type-check, build, and `git diff --check` pass.

## Explicitly Out of Scope

Battlefield schema/migrations, manager mutations, Event result approval
workflow, historical Rank, new Unit authorization, binary media, charts,
leaderboards, and unrelated Statistics changes.
